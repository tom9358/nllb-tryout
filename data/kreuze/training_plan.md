# Training plan for the Gemma/Kreuze corpus

This document tracks the training experiments for
[issue #34](https://github.com/tom9358/nllb-tryout/issues/34). The goal is to
measure whether the synthetic Gemma/Kreuze pairs improve Dutch–Gronings NLLB
translation over models trained only on hand-written Tatoeba data, and then
find a practical training recipe.

RUG data is explicitly outside the scope of these experiments. It must not be
used, committed, included in model artifacts, or otherwise distributed.

## Goals

The questions are deliberately split up:

1. **Does the synthetic corpus contain useful training signal?**
   Compare Tatoeba-only and Tatoeba+Kreuze models under a similar optimizer-step
   budget, starting with Dutch and Gronings only.
2. **Does the corpus improve the best practical multilingual model?**
   Repeat the comparison with the smallest useful set of supporting Tatoeba
   languages.
3. **Can synthetic-label errors be mitigated?**
   If pooling helps but introduces regressions, test a final lower-learning-rate
   stage using only hand-written Tatoeba data.
4. **Does the larger NLLB model benefit more from the additional data?**
   Once the 600M setup works, prioritize a 1.3B run before investing in elaborate
   filtering or weighting.

The main success criterion is performance on held-out, hand-written Tatoeba
data. Matching the synthetic Gemma translations is a useful diagnostic, but it
is not evidence that the output is linguistically correct.

## Data and validation

The generated corpus contains 104,447 pairs. Its regular 98/2 split contains:

| Split | Pairs | Purpose |
|---|---:|---|
| Train before Tatoeba-overlap filtering | 102,358 | Synthetic training data |
| Validation | 2,089 | Per-source diagnostic; never pooled into training |

Every parallel file keeps its own validation set. Pooling adds only
`df_train` to the matching Tatoeba training corpus, so Tatoeba and Kreuze can
still be evaluated separately.

Tatoeba validation uses the global sentence-ID hold-out implemented in
`_global_tatoeba_split()`. Before a parallel corpus is used for training, its
source and target text are now compared against the held-out Tatoeba text for
the corresponding language. Matching ignores casing and whitespace
differences. With the current five-language Tatoeba snapshot, this removes 40
Kreuze training pairs and leaves 102,318.

The overlap count depends on the configured Tatoeba languages because they
jointly determine the global held-out sentence IDs.

## Translation direction

The CSV is ordered as `nld_Latn;gos_Latn`:

- the Dutch sentence was generated by Gemma;
- the Gronings sentence is authentic Kreuze text.

This distinction matters:

- **Dutch to Gronings** uses synthetic Dutch as input and authentic Gronings as
  the training target. This resembles conventional backtranslation.
- **Gronings to Dutch** uses authentic Gronings as input but a potentially
  imperfect Gemma translation as the target.

The current trainer does not duplicate each pair into both directions. For
every sampled pair and epoch, it randomly chooses one direction, with an
approximately 50/50 balance over the complete epoch. If a pair is selected in
every epoch, the probability that it has appeared in both directions after
`E` epochs is:

```text
1 - 2^(1-E)
```

That is about 50% after two epochs and 99.95% after twelve epochs. It is
therefore not guaranteed, especially for a short synthetic-data run or for
rows sampled only in some epochs.

Before the controlled runs, training should gain an explicit alternating
direction strategy. A stable row receives one direction in an epoch and the
opposite direction in the next epoch. For the pooled focus corpus, which is
fully selected by `focus_cap`, two epochs then guarantee one observation in
each direction without doubling the optimizer-step budget. Existing random
direction behavior should remain available for reproducing older runs.

## Focus-cap sampling

`focus_cap` exists to make the configured focus pair, currently
Dutch–Gronings, the largest individual training corpus. Other language pairs
are capped at its size, preventing the hundreds of thousands of
English–German pairs from dominating as a single corpus.

Pooling Kreuze increases the Dutch–Gronings training corpus from roughly
13,000 to roughly 115,000 pairs. Consequently, the cap for every other corpus
also rises. This is consistent with the purpose of `focus_cap`, but it makes a
synthetic-data epoch much larger:

| Five-language setup | Pairs/epoch | Steps/epoch at batch 256 |
|---|---:|---:|
| Tatoeba-only focus-cap | 110,198 | 431 |
| Pooled focus-cap, before overlap correction | about 686,000 | about 2,682 |

Thus two pooled epochs use approximately the same number of optimizer steps as
twelve Tatoeba-only epochs. Epoch counts must never be compared directly.

The focus pair is the largest **individual** corpus; all other language pairs
together still account for most examples in a multilingual epoch. This is
expected, but must be considered when choosing how many supporting languages
to include.

## Sequence of experiments

### Phase 0: data readiness

- [x] Require NLLB language labels in the CSV headers.
- [x] Keep an independent Kreuze validation split.
- [x] Remove language-aware overlap with Tatoeba validation from Kreuze
  training data.
- [x] Measure token-length truncation.
- [ ] Add the explicit alternating direction strategy.
- [ ] Record exact sample and optimizer-step budgets before launching runs.

### Phase 1: cheap Dutch–Gronings signal test

Train two fresh 600M models from the same pretrained weights:

| Run | Training data | Approximate budget |
|---|---|---:|
| Control | Tatoeba Dutch–Gronings only | about 900 steps |
| Treatment | Tatoeba + pooled Kreuze Dutch–Gronings | about 900 steps |

With current corpus sizes, this is approximately eighteen Tatoeba-only epochs
versus two pooled epochs. The exact budget should be fixed in optimizer steps,
not inferred from epoch labels.

This experiment is intentionally cheap and isolates the value of the
synthetic pairs from multilingual transfer. It is a diagnostic, not
necessarily the final model.

### Phase 2: practical multilingual comparison

If Phase 1 is positive, repeat the controlled comparison with supporting
Tatoeba languages. Start with Dutch, Gronings, English and German. Add Spanish
only if previous Tatoeba-only results show enough Dutch–Gronings improvement
to justify the extra language pairs and training time.

Both control and treatment must use:

- the same pretrained 600M model;
- the same Tatoeba snapshot and global validation split;
- the same language set;
- the same seed, optimizer, batch size and maximum length;
- the same direction strategy;
- approximately the same optimizer-step budget.

Evaluate Dutch to Gronings and Gronings to Dutch separately. Metrics on all
other configured Tatoeba directions are regression checks.

### Phase 3: clean-data finish

If pooling improves the model but appears to introduce regressions, branch from
the best pooled checkpoint:

1. continue with the pooled mixture for a small fixed number of steps;
2. continue for the same number of steps using only hand-written Tatoeba data,
   with a lower learning rate.

This control distinguishes the effect of clean finishing from the effect of
simply training longer. The first clean-stage experiment should retain all
supporting Tatoeba languages to reduce catastrophic forgetting.

### Phase 4: follow-up priorities

1. Run the best recipe with NLLB 1.3B.
2. Keep clean and synthetic Dutch–Gronings as separate sampling groups so the
   clean corpus can receive an explicit minimum weight.
3. Try direction-specific weighting if Dutch→Gronings and Gronings→Dutch react
   differently to synthetic data.
4. Investigate conservative quality filtering only if the simpler approaches
   leave clear, attributable problems.

## Token-length measurement

Token counts include NLLB special tokens and were measured on all 104,447
pairs with the 600M tokenizer:

| Column | Language | Median | p95 | p99 | Maximum | Over 43 | Over 48 | Over 64 |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| Generated Dutch | `nld_Latn` | 15 | 35 | 46 | 78 | 1.55% | 0.71% | 0.02% |
| Authentic Gronings | `gos_Latn` | 17 | 39 | 52 | 78 | 3.02% | 1.71% | 0.09% |

The previous five-language model used `max_length=48`. Keeping 48 makes the
first comparison easier to interpret, while 64 almost eliminates truncation
and is a sensible later experiment. If 64 is used, both control and treatment
must use it.

## Evaluation and interpretation

Primary metrics:

- Tatoeba validation BLEU and chrF for Dutch→Gronings;
- Tatoeba validation BLEU and chrF for Gronings→Dutch.

Secondary diagnostics:

- scores on the independent Kreuze validation split;
- all other Tatoeba language directions;
- a fixed manual set of representative Tatoeba and Kreuze examples;
- training loss and the checkpoint at which each validation metric peaks.

Synthetic-validation scores show how well NLLB learns to reproduce the Gemma
dataset. A high score there cannot identify synthetic errors. Synthetic noise
is inferred indirectly when a model fits Kreuze better while hand-written
Tatoeba validation or manual translations become worse.
